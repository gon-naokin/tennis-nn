# テニス班 戦績アプリ

テニス班の中で行ったシングルスとダブルスの試合結果をため、個人の戦績と対戦成績を見るための Web アプリです。
設計の全体像は [DESIGN.md](DESIGN.md) を参照してください。

| 層 | 使うもの | 置き場所 |
|---|---|---|
| 画面 | GitHub Pages（静的 HTML/JS） | `docs/` |
| API | Google Apps Script（GAS）ウェブアプリ | `gas/Code.gs` を Apps Script に貼る |
| データ | Google スプレッドシート | 自分の Google ドライブ |

```
tennis-hm/
├── docs/              GitHub Pages で公開するフォルダ
│   ├── index.html     戦績（試合数・勝率ランキング・最近の試合）
│   ├── players.html   個人成績（種目別・対戦相手別・パートナー別）
│   ├── matches.html   試合一覧（種目と選手で絞り込み）
│   ├── input.html     試合結果入力（幹事のみ）
│   ├── css/style.css
│   ├── img/           キャラクター画像（白フチ付きの透過 PNG）とアプリアイコン
│   └── js/
│       ├── config.js  GAS の URL（ここだけ環境依存）
│       ├── auth.js    入り口パスワード
│       ├── api.js     GAS との通信
│       ├── stats.js   集計ロジック
│       ├── ui.js      画面共通の小道具
│       └── mock.js    サンプルデータ（GAS 未設定のときだけ使う）
├── gas/Code.gs        Apps Script 本体
├── SECRETS.local.md   パスワードの実値（git に入れない）
├── DESIGN.md          設計書
└── README.md          このファイル
```

## 旧版（H vs M 交流戦）から切り替える

すでに旧版のスプレッドシートと GAS を使っている場合の手順です。データはそのまま引き継げます。

1. Apps Script の中身を、新しい `gas/Code.gs` の内容に貼り替えて保存する。
2. エディタ上部の関数選択で **`setup`** を選び **実行** する。
   `matches` の見出しが新しい名前（`a1`、`b1`、`a_games` など）に変わり、`type` 列が足されて既存の試合はダブルスになる。
3. **デプロイ → デプロイを管理 → 鉛筆 → バージョン：新バージョン → デプロイ** と進む。URL は変わらない。
4. 画面側の変更を GitHub に push する。

旧版で H チームだった人は A 側、M チームだった人は B 側として引き継がれます。
`members` の `team` 列は使わなくなります。消しても残しても動きます。

同じ表示名の人が 2 人いると、入力時に名前で区別できません。
`members` の `display_name` を「佐藤A」「佐藤B」のように区別してください。

## セットアップ（初回だけ）

### 1. スプレッドシートと Apps Script

1. Google ドライブで新しいスプレッドシートを作る（名前は「テニス班 戦績」など）。
2. メニューの **拡張機能 → Apps Script** を開く。
3. 最初から入っている `コード.gs` の中身をすべて消し、`gas/Code.gs` の内容を貼り付けて保存する。
4. エディタ上部の関数選択で **`setup`** を選び **実行** する。
   初回は権限の承認を求められる。「このアプリは Google で確認されていません」と出たら **詳細 → （安全ではないページ）に移動 → 許可** と進む。
5. スプレッドシートに `members` / `events` / `matches` の 3 シートが作られる。`members` は空のままでよい。
   試合入力で初めての名前を送ると、`members` に行が自動で追加される。`events` は使わない。

### 2. パスワードを登録する

1. Apps Script エディタ左の **プロジェクトの設定**（歯車）を開く。
2. 下の **スクリプト プロパティ → スクリプト プロパティを追加** で次の 2 つを登録する。

   | プロパティ | 用途 |
   |---|---|
   | `VIEWER_PASS` | 閲覧用パスワード |
   | `ADMIN_PASS` | 幹事用パスワード（入力もできる） |

   値は `SECRETS.local.md` にある。前後に空白を入れないこと。

### 3. ウェブアプリとしてデプロイする

1. エディタ右上の **デプロイ → 新しいデプロイ**。
2. 左上の歯車で種類を **ウェブアプリ** にする。
3. 設定：
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. **デプロイ** を押し、表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーする。

### 4. サイトに URL を設定する

`docs/js/config.js` の `GAS_URL` にコピーした URL を貼る。

```js
GAS_URL: 'https://script.google.com/macros/s/XXXX/exec',
```

### 5. ローカルで動作確認する

`docs` フォルダを簡易サーバーで開く。

```bash
python -m http.server 8787 --directory docs
```

ブラウザで `http://localhost:8787/` を開き、パスワードを入れて戦績が表示されれば OK。
幹事用パスワードで入ると「入力」が現れるので、1 試合入れてスプレッドシートの `matches` に行が増えることを確認する。

### 6. GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る（無料プランで Pages を使うなら Public）。
2. `tennis-hm` フォルダの中身を push する（`SECRETS.local.md` は `.gitignore` で除外済み）。
3. リポジトリの **Settings → Pages** で
   - Source: **Deploy from a branch**
   - Branch: **main**、Folder: **/docs**
   として Save。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける。スマホのホーム画面に追加しておくと便利。

## 試合の入れ方

幹事用パスワードで入り、「入力」を開く。

1. 日付を選ぶ。初期値は今日。過去の試合もここで日付を変えて入れられる。
2. 種目（シングルス／ダブルス）を選ぶ。前回の選択を覚えている。
3. A 側と B 側の名前を入れる。一度登録された人は、下の名前ボタンを押すだけで入る。初めての人は欄に直接入力すると、送信時に `members` へ登録される。
4. スコアに A 側と B 側のゲーム数を 0〜7 の数字で打つ。多い側の勝ち、同数は引き分けになる。確認欄を見てから送信する。
5. 画面の下に、その日に入力済みの試合が出る。入力漏れや重複がないか確かめる。

日付ごとの試合は、「戦績」の日付ごとの表や、「試合」の日付の絞り込みでも見られる。

シートへ直接入れる場合は、`members` に全員がいることを確かめてから `matches` に行を追加する。

| 列 | 入れる値 |
|---|---|
| match_id | 連番（1, 2, 3 …）。重複しないこと |
| date | `YYYY-MM-DD` |
| type | `S`（シングルス）か `D`（ダブルス） |
| a1, a2 | A 側の member_id。シングルスでは a2 を空にする |
| b1, b2 | B 側の member_id。シングルスでは b2 を空にする |
| a_games, b_games | ゲーム数。それぞれ 0〜7 |
| result | 空でよい（API はゲーム数から計算する） |
| entered_at, entered_by, note, deleted, event_id | 空でよい |

入れ終わったら Apps Script エディタで **`checkMatches`** を実行し、ログに「問題は見つかりませんでした」と出ることを確認する。

## 日々の運用

| やること | 方法 |
|---|---|
| 試合結果の入力 | 幹事が幹事用パスワードで入り、「入力」から送る |
| 誤入力の取り消し | `matches` の該当行の `deleted` 列に `TRUE` を入れる |
| スコアの修正 | `matches` の `a_games` / `b_games` を直す（`result` も直すか `recomputeResults` を実行） |
| メンバー追加 | 「入力」で新しい名前を送ると自動で追加される。退部は `active` を `FALSE` に（候補から消える） |
| 名前の入力ミスを直す | `matches` の該当行の ID を正しい人に直し、`members` の誤った行を消す |
| パスワード変更 | スクリプト プロパティの値を変える。サイトの再デプロイは不要。閲覧者は入れ直しになる |
| `Code.gs` を更新したとき | **デプロイ → デプロイを管理 → 鉛筆 → バージョン：新バージョン → デプロイ**。URL は変わらない |

画面は 1 分間データをキャッシュするので、シートを直してすぐ反映されないときは再読み込みするか、ログアウトして入り直す。

## サンプルモード

`config.js` の `GAS_URL` が空のときは `mock.js` のサンプルデータで動く（画面上部に黄色い帯が出る）。
パスワードは何でも通り、`admin` と入れると幹事扱いになる。入力した試合はそのタブを閉じると消える。
GAS を用意する前に画面を確認したいときに使う。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「サーバーの応答を読めませんでした」 | `GAS_URL` が `/exec` で終わっているか。デプロイのアクセスが「全員」になっているか |
| 合っているはずなのに「パスワードが違います」 | スクリプト プロパティ名の綴り（`VIEWER_PASS` / `ADMIN_PASS`）と、値の前後の空白 |
| 入力したのに戦績に出ない | 1 分キャッシュ。再読み込みする。`matches` に行が増えているかも見る |
| 送信すると「type 列がありません」と出る | 新しい `Code.gs` を貼ったあと `setup` を実行していない |
| 新しい名前を送ると「メンバーが見つかりません」と出る | GAS が旧版のまま。`Code.gs` を貼り直し、既存デプロイを「新バージョン」で更新する |
| 「同じ名前の人が複数います」と出る | `members` の `display_name` が重なっている。区別できる名前に変える |
| `Code.gs` を直したのに変わらない | 「新しいデプロイ」ではなく既存デプロイを「新バージョン」で更新したか |
| 特定の試合だけ集計から消えている | スコアや種目がルール外の可能性。`checkMatches` を実行する |
